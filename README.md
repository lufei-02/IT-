# IT-
电商系统 MVP 产品设计与基础技术理解

1. 用户角色与核心场景
   角色	核心场景
消费者 / 买家	浏览商品、查看商品详情、加入购物车、提交订单、支付、查看订单列表 / 详情、取消订单
运营 / 商家人员	创建 / 编辑 / 上下架商品、管理 SKU 与库存、处理订单、安排发货、查看订单状态
平台管理员	管理用户权限、查看平台运营数据、处理异常订单、系统基础配置

3. 核心流程设计
   流程 1：消费者下单与支付流程
正常流程：选择商品 / SKU → 加入购物车 / 立即购买 → 确认收货地址 → 提交订单 → 待支付 → 完成支付 → 已支付
异常场景：库存不足、支付失败、支付超时、商品已下架
状态变更：待支付 → 已支付 / 已取消
流程 2：订单发货流程
正常流程：运营查看已支付订单 → 核对商品 / 地址信息 → 录入物流单号 → 标记发货 → 订单状态变为已发货
异常场景：订单未支付无法发货、无可用物流信息、商品库存不足
状态变更：已支付 → 已发货

4. 简化 PRD
   模块	内容
功能背景	提交订单页是消费者确认订单信息、进入支付环节的核心页面，承接购物车 / 商品详情到支付的关键流程。
用户目标	快速核对商品、地址、金额，顺利提交订单并进入支付环节。
页面字段	收货地址（姓名、电话、详细地址）、商品清单（图片、名称、SKU、单价、数量、小计）、运费、实付总金额、提交订单按钮
业务规则	1. 仅在售商品可提交订单；2. 下单时后端实时校验库存；3. 必须选择有效收货地址；4. 金额自动计算，不支持手动修改
错误提示 / 异常处理	1. 未选地址：请选择收货地址；2. 库存不足：商品库存不足，无法下单；3. 商品下架：该商品已下架，无法下单；4. 网络异常：订单提交失败，请重试
验收标准	1. 正常流程可成功提交订单，生成待支付订单；2. 异常场景精准拦截并给出清晰提示；3. 金额、商品信息展示准确；4. 订单状态正确更新为待支付

5. API 理解题
   
   问题	                          答案
  1. 该 API                       可展示的信息	商品名称、售价、原价、商品 ID、上下架状态、总库存、销量、商品主图、SKU 列表（颜色、单价、库存）
  2. price:19900                  如何展示	199.00 元（API 返回单位为 “分”，需除以 100 转换为元）
  3. status=OFF_SALE              时页面处理	购买按钮置灰不可点击，页面提示 “商品已下架”
  4. 总库存 = 0 时购买按钮展示	    按钮置灰，显示 “缺货”，无法下单
  5. 选择黑色 SKU 时价格与库存变化	价格变为 209.00 元，库存显示 15
  6. API 缺失的字段及原因	        ① 商品详情描述：用户了解商品核心信息；② 商品参数：展示规格、材质等关键信息；③ 运费模板：计算订单运费；④ 服务保障：退换货、保修说明；⑤ 商品分类：用于分类筛选与归属
     
6. 代码逻辑阅读题
     问题	          答案
  1. 函数的核心功能	  判断用户是否可以提交订单
  2. 用户无法提交订单的条件	① 商品状态非在售（已下架）；② SKU 库存≤0；③ 购买数量大于 SKU 可用库存
  3. 当productStatus='ON_SALE'，skuStock=3，buyCount=5时的返回结果	canSubmit: false，原因：Purchase quantity exceeds available inventory
  4. 需补充的校验逻辑	① 用户登录状态校验；② 收货地址有效性校验；③ 商品限购数量校验；④ 用户账号状态校验（是否封禁）；⑤ 订单金额合法性校验

7. 订单状态理解题答案
     问题	              答案
  1. 提交订单后的初始状态	PENDING_PAYMENT（待支付）
  2. 支付成功后的状态	  PAID（已支付）
  3. 商家发货后的状态	  SHIPPED（已发货）
  4. 超时未支付的状态	  CANCELLED（已取消）
  5. 可申请退款的订单状态	PAID（已支付）、SHIPPED（已发货）、COMPLETED（已完成）
  6. 订单状态流转流程	  正常流转：待支付 → 已支付 → 已发货 → 已完成；异常 / 售后流转：待支付 → 已取消；已支付 / 已发货 / 已完成 → 退款中 → 已退款

8. Bug / 异常分析题
       模块	内容
      问题	消费者在商品详情页看到库存为 1，但提交订单时系统提示 “库存不足”，分析原因并给出排查方案
      可能原因	1. 商品详情页库存数据被缓存，未实时更新，展示旧数据；2. 并发下单：用户查看库存后，其他用户抢先下单占用库存；3. SKU 库存与商品总库存数据不一致，前端展示总库存，下单校验 SKU 库存；4. 购物车商品已过期 / 下架，未实时同步状态；5. 前端仅展示缓存库存，提交订单时后端实时校验真实库存；6. 后端库存扣减逻辑异常，未正确同步库存数据
      排查方案	1. 核对商品详情页接口返回库存与数据库真实库存；2. 查询订单日志，确认是否有其他订单占用该库存；3. 校验商品总库存与 SKU 库存数据一致性；4. 检查前端缓存策略，确认库存是否实时刷新；5. 确认提交订单接口是否做了后端实时库存校验；6. 复现场景，抓包对比前后端库存数据

9. 核心数据指标设计
    指标	含义	重要性
    商品详情页 PV	商品详情页浏览次数	衡量商品流量与曝光规模
    加购率	加购用户数 / 商品详情页访问用户数	衡量商品吸引力
    下单转化率	提交订单用户数 / 商品详情页访问用户数	衡量交易流程转化效率
    支付成功率	支付成功订单数 / 提交订单数	衡量支付链路稳定性
    GMV	已支付订单总金额	衡量平台交易规模
    订单取消率	取消订单数 / 总订单数	衡量用户体验与商品问题
    发货时效	订单支付完成到商家标记发货的平均时长	衡量运营履约效率
